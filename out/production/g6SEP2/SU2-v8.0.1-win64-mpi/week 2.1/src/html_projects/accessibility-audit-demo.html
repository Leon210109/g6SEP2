📋 How to Conduct an Accessibility Audit

Step 1: Automated Testing Tools

  1. Chrome Lighthouse:
    • Open Chrome DevTools (F12 or Right-click → Inspect)
    • Click "Lighthouse" tab
    • Check "Accessibility" category
    • Click "Generate report"
    • Review score (0-100) and issues found
  2. axe DevTools:
    • Install axe DevTools browser extension
    • Open DevTools and find "axe DevTools" tab
    • Click "Scan ALL of my page"
    • Review issues categorized by severity
  3. WAVE (Web Accessibility Evaluation Tool):
    • Install WAVE browser extension
    • Click extension icon on any page
    • View visual overlay showing errors, alerts, and features

Step 2: Manual Testing

  1. Keyboard Navigation: Try navigating the entire page using only Tab, Shift+Tab, Enter, Space, and Arrow keys
  2. Screen Reader: Test with NVDA (Windows), JAWS (Windows), or VoiceOver (Mac)
  3. Color Contrast: Check text has sufficient contrast (4.5:1 for normal text, 3:1 for large text)
  4. Zoom Testing: Zoom to 200% and verify layout doesn't break
  5. Focus Indicators: Ensure all interactive elements show visible focus

Step 3: Interpreting Results

Severity Levels: • CRITICAL - Blocks users completely (e.g., no alt text on images, form without labels) • SERIOUS - Major barriers (e.g., poor color contrast, missing ARIA labels) • MODERATE - Significant obstacles (e.g., missing skip links, redundant links) • MINOR - Annoying but not blocking (e.g., missing lang attribute on inline elements) WCAG Conformance Levels: • Level A - Basic accessibility (minimum requirement) • Level AA - Industry standard (most legislation requires this) • Level AAA - Enhanced accessibility (highest level)

Step 4: Prioritize Fixes

  1. Fix all CRITICAL issues first (these completely block users)
  2. Address SERIOUS issues (major barriers to access)
  3. Tackle MODERATE issues (improve overall experience)
  4. Polish with MINOR fixes (achieve excellence)

🚫 Common Accessibility Issues & How to Fix Them

CRITICAL

❌ Issue: Missing Alternative Text

What the audit says: "Images must have alternate text" (WCAG 1.1.1, Level A)

Why it matters: Screen reader users cannot perceive the image content

<!-- BAD: No alt attribute --> <img src="logo.png">
✓ FIXED

✅ Fixed: Descriptive Alt Text

The fix: Add meaningful alt text describing the image purpose

<!-- GOOD: Descriptive alt text --> <img src="logo.png" alt="Company logo featuring a blue shield"> <!-- GOOD: Decorative images --> <img src="decoration.png" alt="" role="presentation">
CRITICAL

❌ Issue: Form Inputs Without Labels

What the audit says: "Form elements must have labels" (WCAG 3.3.2, Level A)

Why it matters: Screen readers can't announce what the input is for

<!-- BAD: Relying only on placeholder --> <input type="text" placeholder="Enter your name">
✓ FIXED

✅ Fixed: Properly Associated Labels

The fix: Use label elements with for/id association

<!-- GOOD: Explicit label association --> <label for="fullName">Full Name:</label> <input type="text" id="fullName" name="fullName">
SERIOUS

❌ Issue: Insufficient Color Contrast

What the audit says: "Text must have sufficient color contrast" (WCAG 1.4.3, Level AA)

Why it matters: Low vision users and users in bright environments can't read the text

This text has poor contrast (2.3:1 ratio) - hard to read!

/* BAD: Contrast ratio 2.3:1 (needs 4.5:1) */ color: #999; background: #ddd;
✓ FIXED

✅ Fixed: Sufficient Contrast Ratio

The fix: Use darker text color to achieve 4.5:1 contrast minimum

This text has good contrast (10.8:1 ratio) - easy to read!

/* GOOD: Contrast ratio 10.8:1 (exceeds 4.5:1) */ color: #333; background: #ddd; /* Check contrast at: https://webaim.org/resources/contrastchecker/ */
MODERATE

❌ Issue: Non-Descriptive Link Text

What the audit says: "Links must have discernible text" (WCAG 2.4.4, Level A)

Why it matters: Screen reader users often navigate by links - "click here" doesn't help

To learn more about accessibility, click here.

<!-- BAD: Generic link text --> <a href="#">click here</a> <a href="#">read more</a>
✓ FIXED

✅ Fixed: Descriptive Link Text

The fix: Make link text describe the destination or action

Learn more about web accessibility guidelines

<!-- GOOD: Descriptive link text --> <a href="#">Learn more about web accessibility guidelines</a> <a href="#">Download the accessibility checklist (PDF)</a>
MODERATE

❌ Issue: No Skip Navigation Link

What the audit says: "Bypass blocks: A mechanism is available" (WCAG 2.4.1, Level A)

Why it matters: Keyboard users must tab through entire navigation on every page

<!-- BAD: No way to skip repetitive content --> <body> <nav>...30 navigation links...</nav> <main>...main content...</main> </body>
✓ FIXED

✅ Fixed: Skip to Main Content Link

The fix: Add a skip link at the top (this page has one - try pressing Tab!)

<!-- GOOD: Skip link appears on focus --> <a href="#main-content" class="skip-link">Skip to main content</a> <style> .skip-link { position: absolute; top: -40px; /* Visible when focused */ } .skip-link:focus { top: 0; } </style>
SERIOUS

❌ Issue: Icon-Only Buttons Without Labels

What the audit says: "Buttons must have discernible text" (WCAG 4.1.2, Level A)

Why it matters: Screen readers announce "button" but don't know what it does

<!-- BAD: Only has title (not read by screen readers by default) --> <button title="Settings">⚙️</button>
✓ FIXED

✅ Fixed: Accessible Icon Buttons

The fix: Add aria-label or visually hidden text

<!-- GOOD: aria-label provides accessible name --> <button aria-label="Settings">⚙️</button> <!-- GOOD: Visually hidden text --> <button> 🏠 <span class="sr-only">Go to homepage</span> </button>

🎯 Accessibility Best Practices Summary

✅ Always Do:

  • Provide alt text for all meaningful images
  • Associate labels with all form inputs
  • Ensure 4.5:1 color contrast for normal text
  • Make all functionality keyboard accessible
  • Use semantic HTML (<header>, <nav>, <main>, <footer>)
  • Provide visible focus indicators
  • Use descriptive link text
  • Test with keyboard and screen readers
  • Include skip navigation links
  • Ensure proper heading hierarchy (h1, h2, h3...)

❌ Never Do:

  • Remove focus outlines without providing alternative
  • Use color alone to convey information
  • Create keyboard traps (can't escape with keyboard)
  • Use placeholder as the only label
  • Hide content from screen readers unless purely decorative
  • Have flashing content faster than 3 times per second
  • Use "click here" or "read more" as link text
  • Disable zoom on mobile
  • Rely solely on automated testing
